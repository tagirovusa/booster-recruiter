# Состояние версии 0.1.3 · 3 ноября 2026

**Это сборка для приёмочных испытаний. Передача клиенту с обещанием полного production-покрытия пока не подтверждена.**

Версия 0.1.3 меняет автоматическую группу на нейтральную для профилей без Open to Work и исправляет подтверждение сообщения в диалоге без поля ввода. Включены предыдущие исправления входа 0.1.1–0.1.2. Причина прежней ошибки установлена чтением уже существующего диалога. В пользовательском запуске после исправления новые сообщения автоматически получили «Отправлено», и очередь продолжила работу. Агент новые отправки не запускал; одна ранее неизвестная отправка исправлена после чтения соответствующего диалога.

## Границы результата

- Пакет macOS рассчитан на Apple Silicon; Intel-сборка отдельно не создавалась. Electron указывает macOS 13+ как технический минимум, фактический тест выполнен на macOS 27.0.1.
- Windows-скрипт ориентирован на Windows 10/11 x64. Windows ARM64 не заявлена.
- Обычные сообщения и сохранение списка реализованы. Отсутствие платного InMail нельзя считать решённым только из-за наличия Premium.
- Нет автоматического определения занятости. Open to Work, Hiring и трудоустройство — разные сведения.
- Данные демо-снимка экрана вымышлены. Они не входят в пустое рабочее пространство нового пользователя.
- Исходный архив не содержит действующих аккаунтов, cookies, паролей и собранных личных профилей.

## Исправление входа в 0.1.1

В установленной версии 0.1.0 воспроизведена ошибка `The browser crash guardian did not start`: служебный процесс запускал собранный executable как Python-интерпретатор; parser отклонял аргументы и завершался с кодом 2. Предыдущая проверка свежего входа была недостаточной: статус auth_required пришёл до завершения фонового запуска, поэтому он ошибочно был принят за подтверждение открытия окна.

Версия 0.1.1 сохраняет защитный guardian и Windows process gate, но добавляет запуск только этих двух встроенных помощников внутри собранного executable. Новая проверка реального helper-процесса воспроизводит отказ старой версии и проходит на исправленной. Дополнительно пройдены frozen runtime/OCR/MCP проверки.

Обновлена установленная копия в `/Applications`. На существующем аккаунте пользователя подтверждено настоящее видимое окно с заголовком `LinkedIn Login, Sign in | LinkedIn`; окно оставалось открытым при повторной проверке через 10 секунд. Пароль и 2FA агент не вводил. Затем пользователь самостоятельно вошёл; локальный API подтвердил правильный профиль и статус ready. Отправки не проверялись.

## Исправление определения аккаунта в 0.1.2

MCP уже вызывал `get_my_profile`, но этот инструмент допускает возврат `/in/me/`, если переход к постоянной ссылке ещё не завершён. Проверка при сохранении аккаунта корректно отвергает этот служебный адрес. Устаревшее поле `url` могло сохраняться в результате MCP даже после завершения перехода в браузере.

Новый обработчик до 15 секунд ждёт адрес и имя открытого профиля, проверяет их стабильность в двух последовательных снимках. Если адресная строка остаётся `/in/me/`, допускается однозначная canonical-ссылка самой страницы, согласованная с og:url при его наличии. Ссылки рекомендованных людей, имя само по себе и ранее сохранённый аккаунт не используются как источник идентичности. Без подтверждения адреса обработка останавливается с понятным сообщением на русском.

Регрессия воспроизведена тестом: `/in/me/` отвергается хранилищем, а реальный адрес после задержанного перехода успешно сохраняется. Проверены неразрешённый адрес, конфликтующие ссылки, смена профиля и запрет отправок при неизвестном владельце. Встроенная автономная проверка использует настоящий Chromium и локально подставленные HTML-страницы; она входит в Windows-скрипт сборки. Это проверка механизма, а не подтверждение успешного входа в живой LinkedIn на Windows.

## Группы и подтверждение отправки в 0.1.3

Все новые профили без распознанного Open to Work получают нейтральную группу. При первом открытии обновлённой версии ранее автоматически распределённые профили переносятся в неё; сохранённые ручные решения остаются. Изменённые кампании требуют нового предпросмотра. Нейтральная группа не означает, что человек работает или не ищет работу.

В реальном ранее отправленном диалоге подтверждено новое сообщение с server message URN и правильными отправителем, текстом и адресатом. LinkedIn убрал поле ввода и показал ожидание ответа. Старый детектор требовал поле ввода даже после отправки. Исправление распознаёт такую страницу по строго проверенному диалогу; остальная защита от ложного успеха и повторной отправки сохранена. Старые неизвестные результаты не меняются массово при обновлении.

Новая InMail-рассылка не реализована. MCP поддерживает ответ в существующий диалог, в том числе InMail, но приложение использует профильный `send_message` для доступного действия Message. Нет отдельного сценария создания нового платного InMail с темой и контролем кредитов.
