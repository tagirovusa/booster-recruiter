# 0.2.8 — приёмочная сборка Business Booster Recruiter

Браузерный компонент включён в проект как `booster_linkedin` / `booster-linkedin-runtime`. Документация, сообщения, метаданные и адреса поддержки относятся к Business Booster. Автор компонента — Daniil Tagirov. Условия Apache-2.0 и лицензии зависимостей сохранены.

Удалены внешняя проверка обновлений компонента и автоматический поиск обращений в чужом репозитории. Диагностические файлы остаются локальными. Публичный MCP-интерфейс приложения, подтверждение действий, форматы сессий и отдельные каталоги аккаунтов сохранены.

## Проверки

- 238 тестов исходного кода прошли на Mac. Четыре новых проверки подтверждают локальную диагностику без сетевых обращений и корректное скрытие устаревших внешних рекомендаций.
- До переименования компонента полный GitHub CI 0.2.7 прошёл на macOS ARM64 и Windows x64: тесты логики, 99 сценариев встроенного Chromium, OCR, замороженный backend, локальный API/MCP и запуск упакованного приложения. Это базовая проверенная версия; она не заменяет повторную проверку 0.2.8.
- Проверка приватности репозитория блокирует сессии, базы, ключи и пути личных рабочих каталогов среди отслеживаемых файлов. Она запускается в CI; тестовые данные и примеры используют вымышленных получателей.
- Сборки и повторная приёмка 0.2.8 фиксируются в GitHub после завершения. До этого документ не подтверждает готовность нового установщика.

## Живые проверки функциональности

- В установленной 0.2.5 собраны и просмотрены две кампании по 20 уникальных профилей на обычном аккаунте и корпоративном Recruiter; оба Excel-экспорта содержат 20 строк профилей. Массовых тестовых отправок этим людям не было.
- Один согласованный платный Recruiter InMail отправлен через интерфейс 0.2.5. История показывает «Отправлено», расход — один кредит, корпоративный баланс изменился 1800 → 1799. Отправка не повторялась.
- Проверены приглашение, принятие и обычное сообщение. Проверка из интерфейса 0.2.6 правильно читает существующий контакт, исходящую историю и входящий ответ «Добро»; новых попыток отправки не возникло, дальнейшие обращения остановлены.
- Адаптер 0.2.7 обнаружил входящий ответ в сохранённой тестовой беседе Recruiter. Это проверка чтения, а не новый полный цикл отправка → ответ через интерфейс Recruiter.

## Незавершённая приёмка

- Установка и живой вход на клиентском Windows-ПК: [задача 2](https://github.com/t4god/booster-recruiter/issues/2). CI проверяет упакованное приложение, но не заменяет вход и работу рекрутера на его компьютере.
- Обычный Premium Career/Business InMail: тестового аккаунта нет, [задача 3](https://github.com/t4god/booster-recruiter/issues/3). Корпоративный Recruiter не подменяет этот тариф.
- Упрощение пустого состояния истории: [задача 4](https://github.com/t4god/booster-recruiter/issues/4). Записи и экспорт сохраняются, но пустой блок старых отправок рядом с результатами автоматизации нужно убрать.

Mac-пакет предназначен для Apple Silicon и использует ad hoc подпись без Developer ID/notarization. Windows x64 пока без сертификата издателя. Прямое распространение предусмотрено, системную защиту отключать не следует.

**Production-ready: false.** Передача клиенту не выполнялась. Выборка профилей и автоматические проверки не доказывают все возможные страницы или тарифные ограничения LinkedIn.
