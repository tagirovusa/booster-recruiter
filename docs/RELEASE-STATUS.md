# 0.2.7 — кандидат для приёмки

Версия 0.2.6 устраняет ложную недоступность обычного сообщения существующему контакту: LinkedIn иногда показывает прошлые сообщения в окне нового сообщения без заголовка беседы. Приложение открывает настоящую беседу через штатный MCP-инструмент и повторно сверяет точный профиль получателя. Только после этого история считается проверенной. Неизвестный результат отправки по-прежнему не повторяется автоматически.

## Подтверждено

- 221 тест логики прошёл на Mac, включая четыре новых сценария: пустая история, найденный ответ, чужая беседа и ошибка чтения.
- На установленной 0.2.5 завершены две кампании по 20 уникальных профилей: обычный LinkedIn и корпоративный Recruiter. Результаты просмотрены в интерфейсе и экспортированы в Excel; в каждом файле 20 строк профилей. Все 40 профилей в этой выборке попали в нейтральную группу; массовых тестовых отправок этим людям не было.
- Через интерфейс установленной 0.2.5 отправлен ровно один согласованный платный Recruiter InMail. Приложение показало «Отправлено», расход составил 1 кредит, остаток в интерфейсе Recruiter изменился с 1800 до 1799. Это наблюдаемый баланс корпоративного контракта, не утверждение о месячной квоте пользователя. История экспортирована в CSV; кампания оставлена на паузе.
- Ранее выполнена цепочка приглашение → принятие → обычное сообщение. В этой тестовой беседе есть входящий ответ. Проверка новым кодом 0.2.6 корректно обнаружила существующий контакт, доступное обычное сообщение, исходящую историю и ответ. Повторной отправки при этой проверке не было.
- В 0.2.5 исправлены варианты Connect, первичные результаты поиска без ссылок на общих знакомых, Unicode-ссылки, проверка адресата в компактном Recruiter, немедленная пауза ожидающей кампании и привязка уведомлений к текущему экрану.
- Для 0.2.5 пройдены 99 автономных сценариев Chromium и 23 группы проверок интерфейса. Их результаты относятся к указанной версии; результаты упакованной 0.2.6 приведены ниже.

## Приёмка 0.2.6 и исправление Windows в 0.2.7

0.2.6 установлена на Mac с сохранением трёх аккаунтов, девяти кампаний и всех кандидатов. Через интерфейс выполнена повторная проверка настоящей беседы: существующий контакт, обычное сообщение, исходящая история и входящий ответ определились корректно; число попыток отправки не изменилось. Прошли проверка подписи, 99 автономных браузерных сценариев, 12 инструментов MCP, запуск упакованного интерфейса и проверка целостности DMG/ZIP.

GitHub Actions на чистом Mac успешно выполнил полный цикл, включая упакованное приложение. На Windows прошли 221 тест и 99 сценариев встроенного Chromium, но затем self-test завершился ошибкой удаления занятого файла `.alive`. Причина — сохранённый диагностический след держал файловый дескриптор до выхода процесса. В 0.2.7 self-test закрывает его в `finally` до удаления временной папки, в том числе при ошибке проверки; сообщение об успехе выводится только после очистки. Добавлены два регрессионных теста. Повторный полный прогон Windows пока ожидается.

Исходники и дальнейшие изменения ведутся в закрытом GitHub-репозитории `t4god/booster-recruiter`; [история предыдущих версий](VERSION-HISTORY.md) восстановлена из архивов.

## Остаётся неподтверждённым

- Установка и работа на реальном Windows x64: вход, переключение аккаунтов, сбор, отправки, сохранение данных после перезапуска. Пользователь выполнит эту проверку позже по `WINDOWS-ACCEPTANCE.md`. CI и наличие исходного ZIP не заменяют её.
- Живой обычный Premium Career/Business InMail: отдельного аккаунта для проверки нет. Офлайн-сценарии существуют; проверка корпоративного Recruiter не подменяет этот сценарий.
- Живое обнаружение входящего ответа именно в корпоративном Recruiter требует отдельного подтверждения; обычный LinkedIn-ответ проверен.

Распространение планируется напрямую, без магазина. Mac использует ad hoc подпись без Developer ID/notarization; Windows пока без издательской подписи. Это ограничения доверия при установке. Системную защиту отключать не следует.

**Production-ready: false.** Передача клиенту и публичный релиз не выполнялись. Наблюдаемые кампании и автоматические проверки не доказывают все возможные страницы LinkedIn; при недостаточном подтверждении приложение показывает понятную причину и сохраняет неопределённый исход для проверки.
