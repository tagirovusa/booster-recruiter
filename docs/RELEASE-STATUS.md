# 0.3.1: исправления по итогам работы на реальных аккаунтах

Список изменений для рекрутера: [что нового в 0.3.1](releases/0.3.1-changes.md). Предыдущая версия: [0.3.0](releases/0.3.0-changes.md).

## Проверено на Mac (Apple Silicon), 08.11.2026
- **Исходный код:** 439 Python-тестов, все наборы интерфейса (`npm run test:ui`), проверка репозитория на приватные данные и сканирование истории на секреты.
- **Сборка:** самопроверка встроенного бэкенда (16 MCP-инструментов), подпись приложения проходит `codesign --verify --deep --strict`.
- **Установка:** 0.3.1 из DMG поверх 0.3.0. Тот же набор интерфейса прогнан на установленном приложении.
- **Реальные данные** (рабочая папка с 12 кампаниями и двумя аккаунтами):
  - кампании, кандидаты и история открываются; новое поле аккаунтов заполнено при первом запуске;
  - поиск в LinkedIn: новая кампания, сбор профилей, распознавание рамки Hiring, «Продолжить поиск» после увеличения числа профилей без дублей;
  - «Посмотреть перед запуском» читает LinkedIn и подставляет имя; отправка не запускалась;
  - «Проверить вход» и «Обновить Recruiter» (контракт и баланс кредитов);
  - «Ответить в LinkedIn» открывает профиль в сессии отправителя;
  - Excel-экспорт, переименование, архив, возврат из архива, удаление, ручная резервная копия;
  - `errors.log` не появился.

## Не проверялось в этой версии
- Отправка приглашений, сообщений и InMail реальным людям: требует согласия владельца аккаунта на конкретных получателей. Логика отправки не менялась с 0.3.0.
- Восстановление копии на рабочих данных: оно требует повторного входа во все аккаунты. Покрыто автоматическими тестами.
- Windows: [инструкция проверки](WINDOWS-ACCEPTANCE.md).
- Подпись: Mac подписан ad hoc, без Developer ID и notarization; macOS может предупредить о неизвестном разработчике.
