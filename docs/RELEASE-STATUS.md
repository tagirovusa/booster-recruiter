# 0.2.0 — кандидат для проверки автоматизации

Это сборка для приёмочных испытаний. После сообщения пользователя о завершении входа версия 0.2.0 установлена на его Mac. Предыдущее приложение 0.1.3 и полная папка пользовательских данных сохранены в отдельной приватной резервной копии. Предыдущие результаты 0.1.3 сохранены в `RELEASE-STATUS-0.1.3.md` и не доказывают работу новых функций.

## Реализовано в исходниках

- Замороженный план: отправитель, получатели, приглашение, обычное сообщение, тема и текст InMail, расписание и бюджеты.
- Экономный и быстрый режимы выбора канала; InMail по умолчанию выключен.
- Подтверждение связи отдельно от признака бесплатного Message/Open Profile.
- Ожидание принятия приглашения, отправка после принятия, проверка ответов, сохранение текста последнего подтверждённого ответа.
- История отдельных действий, консервативное резервирование кредита до вызова браузера, неизвестный результат без автоматического повтора.
- Одна последовательность обращения к профилю между кампаниями/аккаунтами; перенос ожидания приглашения при изменении текстов той же кампании.
- Расписание с часовым поясом, восстановление активных утверждённых планов, пауза, ограниченные бюджеты отправителя по всем кампаниям.
- Фоновая работа через значок приложения; автозапуск включается пользователем только в установленной версии.
- XLSX с отдельной историей обращений; дополнительные поля в CSV. MCP управляет теми же планами; нового инструмента первичного подтверждения нет.

## Что проверяется автономно

Python-тесты хранилища и сценариев, Electron с отдельной временной базой, синтетические DOM в настоящем Chromium с перехватом всех сетевых запросов, собранный runtime, необязательный MCP.

Точные результаты текущего запуска фиксируются отдельно в отчёте 0.2.0. Пройденный синтетический тест не является реальной отправкой InMail и не подтверждает совместимость с интерфейсом конкретного Premium-аккаунта.

## Проверка на аккаунте клиента

Повторный вход после обновления прошёл без нового кода. Сохранены три аккаунта и обе прежние кампании. В отдельной кампании без разрешения отправки собраны три реальных профиля: два нейтральных и один с Open to Work. Чтение вариантов связи обнаружило доступные бесплатные сообщения и возможность приглашения. Реальные приглашения и сообщения при этих проверках не отправлялись.

Выяснилось, что подписка клиента — корпоративный Recruiter. При выборе корпоративного контракта LinkedIn потребовал настроить двухэтапную проверку и не предоставил доступ к кабинету. Пользователь предложил отложить настройку до входа клиента. Включение 2FA само по себе не реализует интеграцию: текущий адаптер работает с обычным LinkedIn, отдельная форма Recruiter ещё требует реализации и проверки. Этот сценарий нельзя заявлять клиенту как готовый.

## Обязательная проверка после входа в Premium

1. Сохранить действующие данные, завершить текущие операции и только после разрешённого обновления установить кандидат.
2. Проверить собственный профиль и изоляцию второго аккаунта.
3. На согласованных тестовых профилях проверить уже существующий контакт, доступное бесплатное сообщение, приглашение и его принятие.
4. Проверить настоящий вид InMail, поле темы и баланс кредитов. При неизвестном виде формы отправка должна оставаться недоступной.
5. Отдельно согласовать точного получателя/текст для реальной отправки и расход одного кредита. Проверить результат и фактический расход.
6. Проверить ответ получателя и отсутствие второй отправки после позднего принятия приглашения.
7. Повторить установку, вход, расписание, трей и сценарии на Windows x64. Сборка Windows сама по себе не подтверждает эти проверки.

## Границы

Поддерживается обычный интерфейс linkedin.com. Отдельные кабинеты Sales Navigator и Recruiter не реализованы. Автоматизация не гарантирует отсутствие ограничений LinkedIn. Без подтверждённой формы и доступного баланса платный InMail не отправляется. Проверяется доступная переписка с конкретным профилем; полнота всех архивных/параллельных потоков LinkedIn не гарантируется.

Новых email-рассылок, автоматических повторных сообщений после молчания, автоматического принятия входящих приглашений, автопокупки кредитов, облачного круглосуточного выполнения, командной синхронизации и автообновлений нет.

Подпись macOS остаётся ad hoc, без Developer ID и notarization. Windows-сертификата нет. Production-ready: false до проверки реальных сценариев, установщиков и согласования распространения.
