# Архитектура и обслуживание

## Процессы

Electron main process запускает собственный Python runtime на случайном loopback-порту. Renderer работает с sandbox, context isolation, без Node.js; доступен только ограниченный IPC. Bearer token остаётся в main process и локальном discovery-файле. API не принимает browser Origin. Приложение не слушает внешние интерфейсы.

Python обслуживает SQLite, очередь и отдельные worker-процессы аккаунтов. Вендорный MCP имеет глобальное состояние, поэтому аккаунты разделены процессами и корневыми папками `accounts/<uuid>/profile`. Cookies и служебные файлы находятся внутри соответствующего аккаунту корня. В один момент выполняется одна браузерная операция приложения.

При подтверждении фиксируются account_id, URL получателей и окончательные тексты. SQLite помечает попытку `sending` до обращения к браузеру. После аварийного завершения `sending` превращается в `unknown`; автоматического повтора нет. По URL действует защита от повторных контактов между кампаниями и аккаунтами. Изменение шаблонов или выбора отменяет незапущенную старую очередь.

MCP-адаптер stdio обращается к этому же локальному API. Он не открывает вторую базу и не выдаёт инструмент первичного подтверждения отправки. Discovery содержит локальный token: это служебный файл, его нельзя включать в экспорт или отправлять в поддержку.

## Хранение

По умолчанию используется Electron userData (`app.getPath('userData')`). Точное имя папки зависит от приложения/платформы. Для изолированных тестов задаётся `BOOSTER_DATA_DIR`; обычному пользователю эта переменная не нужна.

Данные сохраняются в SQLite WAL после каждого изменения. В версии 0.1.1 нет облачного backup, командного сервера, лицензирования или auto-update. Обновлять приложение следует при закрытой очереди с резервной копией SQLite через `sqlite3.Connection.backup`, а не простым копированием одного активного DB-файла без WAL. Сессии аккаунтов в резервную копию профилей рекрутинга не включать.

## Проверки

- `uv run pytest -q`: хранилище, подмена отправителя, невоспроизводимая отправка, пагинация при продолжении, изоляция корней, OCR, авторизация API, безопасный экспорт.
- `npm run test:ui`: настоящее окно Electron и локальный API с вымышленными тестовыми профилями; без LinkedIn-запросов и отправок.
- `uv run python scripts/runtime_smoke.py`: именно собранный исполняемый файл, встроенные Chromium/OCR, настоящий MCP stdio bridge. Синтетический DOM проверяет алгоритм, но не совместимость со всеми вариантами LinkedIn.
- `booster-backend --self-test`: автономная проверка установки без обращения к LinkedIn.

`BOOSTER_BROWSER` предназначен для контролируемых разработчиком проверок с конкретным браузером. Клиентский пакет использует встроенный Chromium. Не открывайте существующий профиль более старым браузером.

## Сборки

PyInstaller собирается на целевой OS. macOS-пакет этой поставки — arm64; Windows-скрипт — x64. Обновление зависимостей выполняется отдельно с изменением lock-файлов и повторной проверкой. Runtime содержит Python, MCP, OCR-модели и браузер; в клиентском пакете нет требования устанавливать их отдельно.

Папки `.venv`, `node_modules`, `runtime`, `build`, `release`, `.build-tools` генерируются. В исходный архив их не включают. `licenses` сохраняет upstream notices; описание поставки и фактические результаты находятся в RELEASE-STATUS.

## Распространение вне магазинов

Публикация в App Store или Microsoft Store не требуется. Для удобного распространения Mac-приложения используется Developer ID и notarization. Локальная ad hoc/неподписанная сборка не заменяет их. Сертификат Apple Development не является Developer ID для передачи клиенту. См. [Apple Developer ID](https://developer.apple.com/developer-id/).

Windows допускает неподписанную сборку, но предупреждения SmartScreen зависят от репутации файла и издателя. Сертификат подписи не гарантирует, что предупреждений сразу не будет. См. [Microsoft Defender SmartScreen](https://learn.microsoft.com/en-us/windows/security/operating-system-security/virus-and-threat-protection/microsoft-defender-smartscreen/).

Для подписанного выпуска сначала нужно проверить и подписать вложенный runtime и browser code, затем приложение, передать его в notarization и проверить ticket/запуск на чистом Mac. Наличие поля `hardenedRuntime` в настройках не доказывает, что такой выпуск прошёл проверку.

## Ограничения LinkedIn

Адаптер читает отрендеренные страницы, не использует приватный Voyager API. Разметка и доступность обычного Message могут меняться. Новые InMail, приглашения и follow-up не реализованы в этой версии. Для их добавления нужны отдельная спецификация канала, точное согласование расхода кредитов и реальные приёмочные проверки; переименование текущей кнопки этого не решает.
