# Приёмка Booster Recruiter на Windows

Эта процедура проверяет конкретную установленную сборку на Windows 10/11 x64. Она дополняет офлайн-сборку и автоматические тесты; сама сборка не подтверждает работу установленного приложения, вход LinkedIn или разделение аккаунтов. На Windows эта процедура ещё не считается пройденной, пока не сохранены результаты на реальном компьютере.

## Перед началом

1. Зафиксируйте версию и SHA-256 именно того установщика, который будете ставить. Очистите старые установщики из папки передачи, чтобы нельзя было случайно выбрать предыдущую версию.
2. Для проверки автономности используйте чистый стандартный профиль Windows без Node.js, Python и uv. Установите приложение обычным пользователем, запишите выбранный путь и результат запуска из меню «Пуск». Если Windows показывает предупреждение для неподписанного файла, зафиксируйте его; не отключайте защиту системы.
3. Используйте только разрешённые тестовые LinkedIn-аккаунты и согласованный пул. Пароль, 2FA и проверку LinkedIn вводите только на странице LinkedIn. Не копируйте сюда файлы аккаунтов, SQLite, browser profile, cookies, bearer tokens или `connection.json`.
4. Для каждой live-кампании заранее выделите не менее **15–20 подходящих профилей** в согласованном тестовом пуле. Если пул меньше, запишите его фактический размер и ограничьте выводы этой выборкой. Не увеличивайте лимит поиска только ради красивого результата.
5. Для проверки отправки выберите только согласованного тестового получателя и отключите каналы, которые не проверяете. Предпросмотр и сбор профилей не отправляют сообщения. **Не разрешайте реальные приглашения, сообщения или InMail автоматически.** Если отдельная проверка отправки нужна, она выполняется вручную только с явным согласием получателя и в заранее согласованном тестовом диалоге.

## Шаги и ожидаемое состояние

Заполняйте строку доказательства для каждого шага: `PASS`, `FAIL`, `BLOCKED` или `NOT RUN`, дата/время, наблюдаемое состояние и имя артефакта. Маскируйте имена и URL в приложенных скриншотах, если нет согласия на их передачу.

### Как трактовать ограничения LinkedIn

Приложение не предполагает заранее известное количество оставшихся приглашений и не задаёт собственный дневной предел. Размер выбранного списка определяет объём утверждённой работы; LinkedIn может остановить её раньше. Реакцию на такое ограничение проверяют синтетическими сценариями, не исчерпанием квот живого аккаунта. Отдельно проверяйте отсутствие автоматического повтора после неизвестного результата.

## Сбор отчёта

Сохраните в одной папке приёмки:

- точную версию/хэш исходного установщика, дату установки, Windows edition/build/архитектуру и путь установки;
- `build-logs/windows-build-report.json` и последний `windows-build-*.txt` от создателя установщика;
- результат `collect-windows-acceptance.ps1` и выходной JSON, созданные на клиентском Windows-компьютере;
- таблицу шагов с PASS/FAIL/BLOCKED/NOT RUN и фактическим числом профилей/аккаунтов;
- только обезличенные скриншоты/экспорт тестового пула. Не прикладывайте папки приложения, app data, SQLite, файлы профилей, cookies, токены или необработанные логи аккаунтов.

Отчёт скрипта подтверждает только версию/ОС/путь, наличие процессов в момент сбора и офлайн self-test. Отдельно вручную отметьте login, account switching, campaign behavior и каждую live-проверку. Нельзя считать 15–20 профилей доказательством прохождения всех сценариев или стабильности всех вариантов LinkedIn DOM.
