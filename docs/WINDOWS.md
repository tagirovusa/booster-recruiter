# Сборка и проверка Windows

Эта инструкция предназначена владельцу проекта, который собирает приложение. Клиенту передаётся получившийся установщик, а не папка с исходниками.

1. Скопируйте архив `Booster-Recruiter-Windows-build-kit.zip` на компьютер с Windows 10/11 **x64** и распакуйте его полностью. Желательно использовать короткий путь, например `C:\BoosterRecruiter`.
2. Откройте распакованную папку и дважды нажмите `BUILD-WINDOWS.cmd`. Не запускайте файл прямо внутри ZIP.
3. Оставьте окно открытым. Первый запуск скачивает Node.js, uv, Python, зависимости и Chromium. Нужны интернет и несколько гигабайт свободного места. Глобальная настройка PowerShell и системный PATH не меняются, права администратора скрипту не нужны.
4. При успехе откроется папка `release`. В ней будет `Booster-Recruiter-0.1.1-Windows-x64-Setup.exe`.
5. Запустите установщик, установите приложение и пройдите проверки ниже. Отсутствие сертификата подписи может вызвать предупреждение Windows; устанавливайте только собственную сборку с известным источником. Отключать защиту Windows для всего компьютера не нужно.

Первый запуск на Windows остановился в загрузке контрольной суммы: PowerShell 5.1 вернул байты вместо строки. В редакции скрипта 2 это исправлено: манифест сохраняется в файл и читается как UTF-8. Проверка SHA256 сохранена. Полный успешный запуск Windows-сборки пока **не подтверждён**. Скрипт специально останавливается при первой ошибке; наличие частичных файлов в `release` не считается успешной сборкой.

## Если инструменты уже установлены

Для Node.js 24 и uv можно использовать PowerShell из папки проекта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-windows.ps1 -UseInstalledTools
```

При ошибке загрузки сначала проверьте интернет-доступ к `nodejs.org`, `github.com`, Python package indexes и CDN Chromium. Не меняйте контрольные суммы вручную. При повторном запуске уже установленные зависимости и архивы могут использоваться из кеша.

## Проверки после установки

- Приложение открывается из меню «Пуск»; терминал и Python вручную запускать не требуется.
- Добавление аккаунта открывает окно LinkedIn. Пароль и 2FA вводятся в LinkedIn, а не в приложении.
- После входа «Проверить вход» показывает правильный профиль отправителя.
- Второй аккаунт создаётся отдельной карточкой, с отдельной сессией. Вход во второй не меняет первый.
- Небольшая кампания сохраняет 3–5 профилей. Проверены имена, ссылки, фото и результаты рамок.
- Пауза завершает текущее действие; повторное открытие приложения сохраняет кампанию.
- Excel и CSV открываются, кириллица отображается правильно.
- В предпросмотре указаны верные отправитель, адресаты и тексты. Контрольную отправку проверяйте только в согласованном тестовом диалоге.

После сборки сохраните `build-logs/windows-build-report.json`. При ошибке понадобится последний `windows-build-*.txt`. Эти отчёты не включают LinkedIn cookies; не добавляйте к ним папку аккаунтов или файлы сессии. Для продолжения работы достаточно сообщить результат сборки и проверки; ошибку можно скопировать из конца журнала.

Обязательная следующая проверка — запуск установщика на чистом Windows-компьютере без инструментов сборки. Она подтверждает автономность пакета, которую одна сборка на машине разработчика не доказывает.
