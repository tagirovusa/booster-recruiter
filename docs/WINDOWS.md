# Сборка и обновление Windows

Инструкция для владельца проекта, который собирает Windows x64 установщик. Клиенту передавайте установщик и краткую запись о его версии и SHA-256, не папку проекта.

## Собрать установщик

1. Из текущего дерева проекта создайте исходный build kit командой `python scripts/source_archive.py --output ../Booster-Recruiter-0.2.8-Windows-build-kit.zip`. Версия в имени должна совпадать с `package.json` (сейчас `0.2.8`). Скрипт исключает `runtime`, `release`, `node_modules`, `.venv`, базы и browser profiles.
2. Перенесите архив на Windows 10/11 x64, полностью распакуйте в короткий путь, например `C:\BoosterRecruiter`. Запускать `.cmd` прямо из ZIP нельзя.
3. Запустите `BUILD-WINDOWS.cmd` и дождитесь завершения. Первый запуск скачивает закреплённые Node.js, uv, Python, зависимости и Chromium; нужны сеть и несколько гигабайт свободного места. Скрипт не меняет системный PATH или глобальную политику PowerShell и не требует прав администратора.
4. При успехе откроется `release`. Имя установщика формируется из текущей версии `package.json`: `Booster-Recruiter-<version>-Windows-x64-Setup.exe`. Удалите или переместите старые установщики из папки передачи, затем проверьте версию и SHA-256 именно выбранного файла.
5. Сохраните `build-logs/windows-build-report.json` и последний `windows-build-*.txt`. Build report фиксирует, что установщик создан и офлайн-тесты прошли; поля установленного приложения и live-входа остаются `false` до ручной приёмки.

Сборка и пользовательская приёмка — разные шаги. Выполните [приёмку на Windows](WINDOWS-ACCEPTANCE.md) на чистом стандартном профиле Windows без Node.js, Python и uv. **Windows-приёмка текущей версии 0.2.8 ещё не заявляется как пройденная.** Сборка на Windows-разработчике сама по себе не доказывает автономную установку на клиентской машине.

## Установка и обновление

1. Убедитесь, что полученный `Setup.exe` соответствует ожидаемой версии из `package.json` и согласованному SHA-256. В папке `release` проверяйте только этот файл, а не любой оставшийся `Setup.exe`.
2. Для первой установки запустите его обычным пользователем и используйте выбранный путь. Приложение приватно распространяется без подписи сертификатом издателя; Windows может показать предупреждение неизвестного издателя. Устанавливайте только файл из известного согласованного источника. Не отключайте Defender или защиту Windows целиком.
3. Для обновления сначала завершите Booster Recruiter через его команду «Завершить работу». Запустите новый установщик поверх установленной версии и проверьте после обновления точную версию приложения. Не удаляйте вручную локальные данные приложения или каталоги аккаунтов: там находятся кампании и отдельные сессии.
4. После обновления проверьте карточки отправителей и статусы кампаний. Если LinkedIn потребовал повторный вход, выполняйте его в окне LinkedIn и затем повторите «Проверить подключение». Успешная сборка не подтверждает действительность конкретной LinkedIn-сессии.

## Если инструменты уже установлены

В PowerShell из распакованной папки проекта можно использовать Node.js 24 и uv из PATH:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-windows.ps1 -UseInstalledTools
```

При сбое загрузки проверьте доступ к источникам инструментов и пакетным индексам. Не меняйте контрольные суммы вручную. Скрипт останавливается при первой ошибке; частичный файл в `release` не считается успешным установщиком.

## После установки

Пройдите [Windows acceptance runbook](WINDOWS-ACCEPTANCE.md). Он проверяет запуск установленного приложения, изоляцию двух отправителей, bounded-поиск, паузу/сохранение после перезапуска, лимиты и экспорт. Live-отправка не нужна для базовой приёмки; если она отдельно согласована, её выполняют только вручную в тестовом диалоге с согласием получателя.

Для дополнительного read-only отчёта запустите PowerShell-скрипт из исходного build kit, пока приложение открыто:

В команде ниже замените `<путь установки Booster Recruiter>` на выбранный в установщике каталог, например `C:\Users\<имя пользователя>\AppData\Local\Programs\Booster Recruiter`.

```powershell
New-Item -ItemType Directory -Force .\acceptance-evidence | Out-Null
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\collect-windows-acceptance.ps1 `
  -InstallDirectory "<путь установки Booster Recruiter>" `
  -OutputDirectory .\acceptance-evidence
```

Если установили в другой каталог, укажите его в `-InstallDirectory`. Скрипт записывает Windows build/architecture, install path, версию/хэш bundled backend, текущие имена процессов и результат локального `--self-test`. Он не читает app data, базу, профили браузера, cookies, tokens, переменные среды или командные строки процессов. Сам self-test работает на временных данных и не обращается к LinkedIn. Передайте JSON только после просмотра.

В build/transcript и acceptance отчёты не включайте папку аккаунтов, cookies, `connection.json`, SQLite или необработанные browser/worker логи. Если нужна помощь, достаточно версии, статуса шага, точного сообщения об ошибке и соответствующего build/acceptance отчёта после проверки на секреты.
