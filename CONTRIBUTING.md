# Контроль изменений

Основной репозиторий: `t4god/booster-recruiter`, закрытый. `main` хранит принятую историю проекта. Исправления и новые функции выполняются в отдельных ветках и проходят через pull request с описанием поведения и проверки.

## Обычный цикл

1. Создать ветку от актуальной `main`: `fix/краткое-имя` или `feature/краткое-имя`.
2. Внести небольшой законченный набор изменений. Зафиксировать его коммитом с понятным назначением.
3. Прогнать тесты, сборку и нужные проверки интерфейса. В pull request указать, что проверено автоматически, что проверено в установленном приложении и что остаётся неподтверждённым.
4. Открыть pull request. GitHub Actions проверяет исходники, собирает macOS ARM64 и Windows x64 и запускает приложение с отдельными тестовыми данными. Внешние отправки не входят в CI.
5. После проверки объединить изменения в `main`. Версия приложения отмечается тегом `vX.Y.Z`; релиз содержит установщики и их SHA-256 только после соответствующей приёмки.

Успешный CI не подтверждает вход в настоящий LinkedIn, доступность тарифов или успешность отправки. Эти результаты фиксируются отдельно в `docs/RELEASE-STATUS.md`. Тег обозначает версию исходников, а не автоматически подтверждённый клиентский релиз.

В репозиторий входят исходники, тесты, сценарии сборки, документация и лицензии. Браузерные профили, cookies, токены, базы аккаунтов/кандидатов, экспорт, реальные снимки страниц и локальные журналы остаются вне Git. Пароли и коды входа вводятся только в соответствующем сервисе.

История до подключения GitHub восстановлена из сохранённых архивов. Её источники и пробелы перечислены в [истории версий](docs/VERSION-HISTORY.md). Не изменяйте опубликованные теги и не переписывайте опубликованную историю без отдельной причины.
